agentgrid.

A local, zero-dependency dashboard over every Claude Code and Codex session on your machine — with a daily notepad whose checkboxes are the todo list.

Which agent needs me? Which is still working? What is each one actually doing?

The problem it solves

Run a few coding agents at once and the operating system gives you almost nothing to tell them apart: a window title, maybe. A session blocked at a permission prompt looks exactly like one that finished twenty minutes ago and one that is mid-command. Auto-generated titles are derived from the first prompt, so three sessions started from the same ticket all read identically. And sessions living inside an editor's terminal have no visible list at all.

agentgrid answers the three questions above at a glance, and does the two things that follow from answering them: starts a new agent in any repo, and gets you into the session that needs you.

The board: a column per state. The amber stub means a human is needed; the blue stub means an unread reply; hovering a card reveals its own Open ↗.

Position carries state, so colour does not have to. The palette is near-monochrome with one warm accent, used only where something is genuinely waiting on a human — which is why a screen of twenty agents stays calm instead of festive.

What it deliberately is not

  • Not a daemon. Both front ends stop when you close them. No service, no launch agent, no port left listening.
  • Not a package. Python standard library only. No pip install, no virtualenv, no build step, no npm.
  • Not a terminal in the browser. An interactive session's keyboard belongs to the terminal that owns it. Reading is the ceiling, and reading is always safe — transcripts are opened read-only.
  • Not remote. The web server binds loopback only and every request needs a per-run token.

Every fact on a card comes from an interface the CLIs already expose — their JSON output and the session transcripts on disk. Nothing is scraped from a rendered screen.

Make it work

You need

  • macOS (or Linux, terminal grid only — the Terminal.app integration degrades to a printed command elsewhere)
  • Python 3.10 or newer — already on every recent Mac
  • the claude CLI on PATH
  • optionally the codex CLI, if you want Codex agents on the board too

Install

Installation is a clone, a chmod, and a symlink. There is nothing to build and nothing to download beyond the repo itself.

git clone <repo> agentgrid
cd agentgrid
chmod +x bin/ag
ln -s "$PWD/bin/ag" ~/.local/bin/ag   # any directory on your PATH

No symlink? python3 -m agentgrid from the repo root does the same thing.

Run

ag --web    # the browser board — the everyday front end
ag          # the curses grid, for when you are already in a terminal

The web command prints one URL and opens it:

agentgrid web UI
  http://127.0.0.1:8787/?t=Kq83…
  projects from: /Users/you, /Users/you/Documents/GitHub
  loopback only, token-gated, stops when you Ctrl-C this terminal.

The ?t= token is minted per run and is the only way in — a bare http://127.0.0.1:8787/ gets a 403. Useful flags:

FlagWhat it does
--root DIRwhere to scan for repos (repeatable; replaces the defaults)
--port 9000pick the port; falls back to a free one if taken
--no-openprint the URL without launching a browser
--filter, --cwd, --no-mouse, --refreshgrid-only options

Reading the board

Five columns, left to right in descending order of how likely you are to act: Needs you, Working, Replied, Done, Idle. The settled two are hidden by default with their counts kept on the toggles.

Replied is not Done on purpose. The CLI's done means the turn ended — an agent asking "shall I push?" reports done with the conversation wide open. So ended turns file under Replied, and Done is reserved for the one state only a human can set, by dragging a card there.

  • Cards are two lines — name, then where and when. Everything else is one click away in the side panel: rename, tags, transcript, subagents, move-to buttons, and the notes that mention the session.
  • Getting in. Hover a card and click Open ↗ (or use Open in Terminal in the panel). A background session is genuinely joined via claude attach in a new Terminal.app tab; clicking twice focuses the existing tab rather than opening a second attach. An interactive session's real tab is brought to the front where possible — never resumed, which would fork the conversation.
  • Unread is a blue stub on Replied cards, cleared by opening the card and returning by itself when the agent says something new. It is stored as how far you had read, not as a flag — so nothing has to notice new output for you.
  • Manual moves expire honestly. Dragging a card records the reality it was made against; when the session's real state moves on, the override clears itself. Working is neither a source nor a destination — stop the session instead.
  • New agent (n) asks for Name, Project, Engine (Claude or Codex), Model, Task — name first, because it is the thing you will look for on the board afterwards. The agent appears within a couple of seconds and outlives the browser.

The notepad

The board is where you sit while agents run, so it carries the day's notes. The pad is a plain textarea over plain markdown files — one directory per day, one file per page, the filename is the page title. Any line matching - [ ] text becomes a live todo in the rail on the right, tickable from there. Ticking rewrites exactly one character in the file.

# Kamil sync - [x] send the branch to Abhishek - [ ] chase Kamil tomorrow @edge-gating - [ ] update PROJ-993 by friday notes from the call: replay path never read the flag for drags…
To do
chase Kamil @edge-gatingtomorrow
update PROJ-993 fri
send the branch

The pad and its rail. Due dates are written in the sentence and shown as chips; @mentions link lines to sessions; ticket keys become links.

  • Writing shortcuts: -[] then space expands to a checkbox; Enter continues a list; Tab nests — on checkbox lines only.
  • Due dates parse from natural phrases — tomorrow, in 3 days, march 3rd, by friday, #wed — resolved against the day the note belongs to, never the clock. A bare weekday deliberately does not count: "wednesday sync" is a meeting name, not a deadline.
  • Unfinished items carry forward under their own heading, so the pad is a working list rather than a diary.
  • Pages can be grouped, reordered, and set to repeat — a Friday 1-1 appears on Fridays and nowhere else, fresh each time.
  • Typing @ offers the live sessions and inserts a slug that links both ways: the rail links to the session, and the session's panel lists every line that names it, with a quick-add box.

Notes and todos are one document because anything that has to be re-entered somewhere else does not get done. The files stay plain markdown on disk — greppable, hand-editable, committable — and the filesystem is the source of truth: a page added in Finder appears, one deleted there disappears.

Codex sessions

If the codex CLI is installed, its sessions join the board automatically — discovered from the rollout files Codex writes under ~/.codex/sessions/, with titles from Codex's own session index. A session mid-task shows as Working; one whose last task completed files under Replied; sessions leave the board after a day without activity. Codex cards carry a · codex marker, and everything except joining works on them — there is no attach command to join with, and the card says so rather than guessing.

Needs you, and the optional hook

Needs you works with zero setup, by two separate paths: a background agent reports blocked directly, and an interactive session stopped at a question or permission prompt reports waiting — both map straight onto the column. The bundled hook is an optional refinement: it also records why a session is waiting, and clears the wait the instant you reply rather than on the next poll.

If you want that, add both entries to ~/.claude/settings.json, pointing at the hook script in your clone:

{
  "hooks": {
    "Notification": [
      { "hooks": [ { "type": "command",
          "command": "python3 /path/to/agentgrid/hooks/agentgrid_notify.py" } ] }
    ],
    "UserPromptSubmit": [
      { "hooks": [ { "type": "command",
          "command": "python3 /path/to/agentgrid/hooks/agentgrid_notify.py" } ] }
    ]
  }
}

The hook always exits 0 and never prints, so a failure in it can never block or disrupt the session it observes.

One cosmetic step for tab naming: Terminal.app appends the running process to tab titles. Turn that off under Terminal → Settings → Profiles → Window → Title, or every attached tab reads "claude".

The terminal grid

ag with no flags draws the same fleet as cards in your terminal — three views deep: grid → session detail → transcript, with Enter going deeper and Esc backing out. The keys that matter: Tab jumps to the next session needing you, a attaches, x stops (it asks first), ⇧R renames, f cycles filters, q quits. Cards are ordered so anything waiting on a human sorts to the top left.

Security posture, plainly

The web server can start processes, so it is treated accordingly: it binds 127.0.0.1 only, mints a fresh token every run, refuses every request without it, and sends no-embedding and no-referrer headers so the token cannot leak. Agents can only be started in directories the project scan already knows. Do not expose the port off the machine.

If something looks wrong

SymptomFix
"claude CLI not found on PATH" Install Claude Code's CLI or fix PATH; the board says this rather than crashing.
403 in the browser You opened the bare URL. Use the full one agentgrid printed — the ?t= token is the way in, and it changes every run.
Open ↗ says automation was blocked Allow your terminal under System Settings → Privacy & Security → Automation, then retry.
A blocked session is not in "Needs you" Restart ag --web — status mappings are read at start. Both paths (background blocked, interactive waiting) work without the hook.
A repo is missing from the project picker The scan is one level under each root. Add --root ~/work/clients for deeper layouts; the roots scanned are printed at startup.
Codex sessions absent Only sessions active in the last 24 hours appear; start one and it shows up within seconds.
Port already in use Nothing to do — a second instance falls back to a free port and prints it.
